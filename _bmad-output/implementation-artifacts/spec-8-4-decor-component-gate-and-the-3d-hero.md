## Intent

**Problem:** `src/decor/` is an empty `.gitkeep`, three.js is not installed, and the Setup hero (section 01) has no art column: `hero-bloom-orange.webp` sits unused in `public/decor/artwork/` and there is no Y2K chrome piece. AD-12 requires one isolated, gated, freezable, text-free `<Decor>` layer that never slows setup (NFR-3, NFR-7).

**Approach:** Add `three@0.186.1` and `@types/three@0.186.0`. Build `src/decor/` as one client component `<Decor scene="hero"|"shuffle" mode="ambient"|"shuffle"|"frozen" className>` that renders a static still from `public/decor/chrome/` immediately (SSR markup), then after mount runs a pure gate (`decorGate(env)`, no three import) over an injected environment (WebGL2, reduced motion, `html[data-motion]`, `deviceMemory`, `hardwareConcurrency`, `saveData`). Only when the gate passes, and only the first time `mode !== "frozen"`, does it load `./DecorScene` with `next/dynamic` `ssr:false`; that file and `src/decor/scenes/*` are the only importers of three. The scene is plain three.js: a chrome ring-and-blob hero with cursor depth (40px, eased 900ms), and a stars-in-the-margins shuffle scene (used by 8.5). The loop runs through `renderer.setAnimationLoop`, stops on `frozen` and on `document.hidden`, and everything is disposed on unmount. `SetupHero` gains a desktop-only right column holding the hero bloom and `<Decor scene="hero" mode="ambient">`. `/` stays static; the three chunk never appears in the page's HTML script list.

- `src/decor/useDecorGate.ts` (`"use client"`): `useDecorGate(): boolean | null`; `null` before the mount effect, then `decorGate(readDecorEnvironment())`; re-evaluates on the reduced-motion `MediaQueryList` `change` event and on a `MutationObserver` of `<html>` with `attributeFilter: ["data-motion"]` (the Motion toggle and a persisted `ambientMotion:false` both arrive through that attribute via `MotionSync`, so Decor never reads the store). The WebGL probe runs once per mount, not per re-evaluation.
- `src/decor/Decor.tsx` (`"use client"`): `export type DecorSceneName = "hero" | "shuffle"; export type DecorMode = "ambient" | "shuffle" | "frozen"; export type DecorState = "fallback" | "loading" | "running" | "frozen"; export interface DecorProps { scene: DecorSceneName; mode: DecorMode; /** Position and size; Decor never positions itself (same contract as ChromePiece). */ className: string }`.
  - `export function DecorView({ scene, state, className, children })` is pure markup: `<div data-decor data-decor-scene={scene} data-decor-state={state} aria-hidden="true" className={`pointer-events-none absolute overflow-hidden ${className}`}>` containing the fallback `next/image` (`alt=""`, `aria-hidden`, `FALLBACK[scene]`: hero → `/decor/chrome/chrome-ring.webp` 631×640 with `absolute inset-0 h-full w-full object-contain`; shuffle → `/decor/chrome/chrome-burst.webp` 612×640 with `absolute top-1/2 right-header-inset w-[12vw] -translate-y-1/2`), for `scene === "shuffle"` an invisible keep-out probe `<div data-decor-keep-out className="invisible absolute inset-y-0 left-1/2 w-safe-area-width -translate-x-1/2" />` (the scene measures it, so CSS resolves `min(56.25vh, 640px)`), then `children` (the scene, when mounted).
  - `export function shouldRequestScene(requested: boolean, gate: boolean | null, mode: DecorMode): boolean` = `requested || (gate === true && mode !== "frozen")` (pure; the chunk is requested the first time the layer has something to animate, so a Stage opened already held never downloads three).
  - `export function Decor(props)`: `gate = useDecorGate()`; `requested` latches via `shouldRequestScene`; renders `<DecorView state={state}>{gate === true && requested ? <DecorScene scene mode onState={setSceneState} /> : null}</DecorView>` where `const DecorScene = dynamic(() => import("./DecorScene"), { ssr: false })` is declared at module scope. `state` is `"fallback"` while the gate is `null`/`false` or the scene is not requested, `"loading"` once requested until the scene reports, then whatever the scene last reported (`"running"` | `"frozen"`). When the gate flips to `false` later (Motion toggled off, reduced motion switched on) the scene unmounts (dispose runs) and the state returns to `"fallback"`.
- `src/decor/DecorScene.tsx` (`"use client"`; the only React file that imports `three`): props `{ scene: DecorSceneName; mode: DecorMode; onState: (state: "running" | "frozen") => void }`. Renders `<canvas aria-hidden="true" className={`absolute inset-0 h-full w-full transition-opacity duration-(--dur-decor-fade) ${shown ? "opacity-100" : "opacity-0"}`} />`. In one mount effect: `new WebGLRenderer({ canvas, alpha: true, antialias: true, powerPreference: "low-power" })`, `setPixelRatio(Math.min(devicePixelRatio, config.decor.maxPixelRatio))`, `setClearAlpha(0)`, a `PerspectiveCamera(35, aspect, 0.1, 50)` at `z = 6`, a `ResizeObserver` on the canvas parent calling `renderer.setSize(w, h, false)` and updating the camera, `const handle = SCENES[scene]({ scene, camera, colors: readDecorColors(), canvas })`, then `renderer.setAnimationLoop(tick)`. `tick(timeMs)` computes `dt` (clamped to 0.1s), calls `handle.update(dt, pointer)`, `renderer.render(scene, camera)`, and after the first rendered frame sets `shown` and calls `onState("running")`. A separate effect on `mode`: `"frozen"` → `renderer.setAnimationLoop(null); onState("frozen")` (last frame stays on the canvas); any other mode → `setAnimationLoop(tick); onState("running")`. `visibilitychange`: `document.hidden` → `setAnimationLoop(null)`; visible and `mode !== "frozen"` → `setAnimationLoop(tick)`. Pointer (hero only): `window.addEventListener("pointermove", …, { passive: true })` storing `pointer = { x: (clientX / innerWidth) * 2 - 1, y: -((clientY / innerHeight) * 2 - 1) }`; the canvas itself is `pointer-events: none`, so the listener must be on `window`. Cleanup: remove listeners, disconnect the observer, `setAnimationLoop(null)`, `handle.dispose()`, `renderer.dispose()`, `renderer.forceContextLoss()`.
- `src/decor/scenes/types.ts`: `export interface SceneContext { scene: THREE.Scene; camera: THREE.PerspectiveCamera; colors: DecorColors; canvas: HTMLCanvasElement }`, `export interface SceneHandle { update(dtSec: number, pointer: { x: number; y: number }): void; dispose(): void }`, `export type DecorColors = Record<"foilA" | "foilB" | "foilC" | "foilD" | "cream" | "night" | "grape" | "lilac", THREE.Color>`, and `readDecorColors()` which reads `--color-foil-a|b|c|d`, `--color-cream`, `--color-night`, `--color-grape`, `--color-lilac` with `getComputedStyle(document.documentElement).getPropertyValue(name).trim()` into `new THREE.Color(...)` (tokens stay the single source; no hex literals in `src/decor`). Also `pxToWorld(camera, canvasHeightPx)` = `(2 * camera.position.z * Math.tan(THREE.MathUtils.degToRad(camera.fov / 2))) / canvasHeightPx`.
- `src/decor/scenes/hero.ts`: `export function buildHeroScene(ctx): SceneHandle`. A `Group` holding three chrome rings (`TorusGeometry(1.0|1.35|1.7, 0.045, 24, 96)`, tilted about distinct axes) around one inflated blob (`IcosahedronGeometry(0.55, 3)`), all `MeshStandardMaterial({ metalness: 1, roughness: 0.15, color: colors.cream })`; lit by `HemisphereLight(colors.cream, colors.night, 1.2)` plus three `PointLight`s in `foilA`, `foilB`, `foilD` placed around the group (chrome reads as chrome through colored highlights; no environment map, no texture, no asset request). `update`: rings spin at `config.decor.hero.spinRadPerSec` on their own axes; the group's position eases toward `pointer * depthPx * pxToWorld` with `factor = 1 - Math.exp(-dtSec * 1000 / config.decor.hero.depthEaseMs)` (DESIGN → Elevation & Depth: the three.js piece takes the nearest depth, 40px, eased over 900ms). `dispose` disposes every geometry and material and removes the group.
- `src/decor/scenes/shuffle.ts`: `export function buildShuffleScene(ctx): SceneHandle`. `config.decor.shuffle.starCount` chrome stars (`OctahedronGeometry(0.22)` scaled `(1, 1, 0.3)`, same material family, lights in `foilB`, `foilC`, `grape` over the lilac ground) placed only in the two side bands: measure `ctx.canvas.parentElement.querySelector("[data-decor-keep-out]")` with `getBoundingClientRect()` on build and on every `update` where the canvas size changed; a star's `|x|` in CSS px is at least `keepOutHalfWidth + config.decor.shuffle.keepOutMarginPx`, converted with `pxToWorld`. `update`: stars spin at `spinRadPerSec` and drift vertically at `driftPxPerSec`, wrapping at the band's top and bottom. Nothing is ever placed inside the keep-out, so the column (and the Brief) never has 3D under it.
